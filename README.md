# Практикум: семь прикладных проектов по лекции 9

Маленькие приложения, в которых нужно применить всё, что разбирали на лекции
и семинаре 9: протоколы `__iter__`/`__next__`, классы-итераторы, генераторные
функции и выражения, `yield from`, двусторонний канал `send`/`throw`/`close`,
вторую форму `iter(callable, sentinel)` и модуль `itertools`. Ничего из более
поздних лекций (декораторы, асинхронность, контекстные менеджеры) не
понадобится.

Проекты специально «молодёжные»: думскролл-лента, рекомендации «для тебя»,
плейлист на вечеринку, чат-копилка, модерация чата, стрим чанками и
автокомплит. Идти лучше по порядку — каждый следующий опирается на приёмы
предыдущих.

Правило одно: **сначала решаем, потом сверяемся с решением**. Каждый проект —
это отдельная папка, в которой рядом с заготовкой лежат её тесты; пока подзадача
не сделана, она честно падает с `NotImplementedError`.

Ориентир по времени — 40–50 минут на проект. Если проект «не встаёт», проще
перейти к следующему и вернуться: темы пересекаются.

## Как решать

Из этого каталога:

```bash
python3 -m pytest -q                    # все семь проектов
python3 -m pytest -q doomscroll         # только один проект
cd doomscroll && python3 -m pytest -q   # или из папки проекта
```

Тесты импортируют заготовку по короткому имени (например,
`from project01_doomscroll import Feed`), поэтому команды одинаково работают и
из корня, и из папки проекта: корневой `conftest.py` добавляет каталог в
`sys.path`, а pytest — ещё и папку самого теста.

Поначалу почти всё красное: каждая подзадача бросает `NotImplementedError`.
Открывайте заготовку, читайте докстринг — там сказано, что вернуть и на что
не попасться, — и пишите реализацию. Когда файл готов, его тесты (даже вместе
с остальными) должны стать зелёными.

Проект считается решённым, когда тесты зелёные и вы можете объяснить каждое
приёмочное место: почему `iter(feed) is not iter(feed)`, а `iter(cursor) is
cursor`; почему генераторная функция не выполняет тело при вызове; почему
`send` без раскрутки падает с `TypeError`; почему состояние наружу отдают
копией; зачем уборка живёт в `finally`; и почему в `iter(callable, sentinel)`
стоп-условие проверяется через `==`. Именно про «почему так» и спрашивают на
коллоквиуме.
